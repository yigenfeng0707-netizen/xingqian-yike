Architecture & Story

为什么做「行前一刻」

上班族出门前常在高德、地铁 App、天气、日历之间来回横跳，信息够多，决策却更累。 现有产品擅长「列选项」，不擅长在约束下给出唯一可执行行动，更少在延误发生时主动改线。我们把这一步做成 Agent。

Agent 架构

  1. 1. weather_lookup

    感知目的地天气与出行建议，影响缓冲与骑行可行性。

  2. 2. route_options

    基于北京海淀/中关村/国贸等高保真 Mock，按偏好枚举地铁/公交/骑行/打车及混合方案。

  3. 3. leave_time_planner

    行程时长 + 天气/可靠度/时段缓冲 → 倒推「必须出门」时刻。

  4. 4. replan_on_disruption

    延误触发后重排：偏向高可靠、混合接驳或末端打车，输出新的唯一行动。

技术栈

  • Next.js App Router + TypeScript + Tailwind
  • 浏览器内 Agent 编排（planner.runPlan / runReplan），UI 展示完整工具轨迹
  • 默认离线高质量北京 Mock；若设置 OPENAI_API_KEY 则叙事层可走 LLM

比赛故事（10.13–10.22）

  • · 锁定切口：通勤决策 Agent（唯一行动，而非全能助手）
  • · 四工具闭环 + 三条 Demo 剧本（晴天/延误/改目的地）
  • · 提交四件套：可运行 Demo、公开仓库、≤6 页 PPT 文案、海报 brief

落地路径

短期：日历「下一场会议」+ 天气/路况 API 真接，推送出门提醒。 中期：企业班车/园区通勤场景试点。长期：延误保险式「到达保障」订阅。
